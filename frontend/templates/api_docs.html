API Documentation

Complete reference for the HealthTrack REST API — all endpoints built and owned by this project.

Base URL
http://13.60.233.151:5000
All endpoints are prefixed with this base URL. For local development use http://localhost:5000.
13 Endpoints
2 Auth · 6 Health · 5 Analytics
JWT Authentication
Bearer token, 2-hour expiry
DynamoDB Backed
AWS eu-north-1 · On-demand
Authentication

Most endpoints require a JWT Bearer token. Include it in every request header:

Authorization: Bearer <your_token>
Obtain a token via POST /api/auth/login. Tokens expire after 2 hours. Endpoints marked No Auth are public.
Response Format

All responses use a consistent JSON envelope:

Success
{
  "success": true,
  "data": { /* payload */ }
}
Error
{
  "success": false,
  "error": "Human-readable message"
}
StatusMeaning
200OK — request succeeded
201Created — resource created successfully
400Bad Request — validation error
401Unauthorized — missing or invalid token
404Not Found — resource does not exist
503Service Unavailable — upstream dependency error
Authentication API Base path: /api/auth
POST /api/auth/register No Auth Create a new user account

Registers a new user. Email must be unique. Passwords are hashed (bcrypt) before storage.

Request Body (JSON)
FieldTypeReq?Description
emailstringYesValid email address
passwordstringYesMin 8 characters
namestringYesDisplay name
Example Request
POST /api/auth/register
Content-Type: application/json

{
  "email":    "alice@example.com",
  "password": "mypassword123",
  "name":     "Alice Smith"
}
201 Created
{
  "success": true,
  "data": {
    "message": "Account created successfully."
  }
}
400 Error
{
  "success": false,
  "error": "Email already registered."
}

      Health Records API
      Base path: /api/health — Auth Required
    


    
    

      

        POST
        /api/health
        Auth
        Create a health record
        
      

      

        
Creates a new health record for the authenticated user for a given date. Each user may have at most one record per date. The record is written to DynamoDB (partition key: user_id, sort key: date).


        

          

            
Request Body (JSON)

            

              
FieldTypeReq?Description

              
                
datestringYesYYYY-MM-DD format

                
stepsintegerNoSteps walked that day

                
heart_rateintegerNoResting heart rate (bpm)

                
sleep_hoursfloatNoTotal hours of sleep

                
sleep_timestringNoBedtime — 24hr HH:MM

                
wake_timestringNoWake time — 24hr HH:MM

                
mealsarrayNoList of meal description strings

                
exerciseobjectNo{"type","duration_minutes","frequency_per_week"}

                
weight_kgfloatNoBody weight in kilograms

                
height_cmfloatNoHeight in centimetres

                
calories_burnedintegerNoTotal calories burned

              
            

          

          

            
Example Request

            
POST /api/health
Authorization: Bearer <token>
Content-Type:  application/json

{
  "date":          "2026-03-31",
  "steps":         9200,
  "heart_rate":    68,
  "sleep_hours":   7.5,
  "sleep_time":    "23:00",
  "wake_time":     "06:30",
  "meals":         ["oats", "grilled chicken"],
  "exercise":      {
    "type":              "running",
    "duration_minutes":  30,
    "frequency_per_week":4
  },
  "weight_kg":     72.5,
  "height_cm":     175,
  "calories_burned": 450
}

          

        


        

          

            
201 Created

            
{
  "success": true,
  "data": {
    "user_id": "alice@example.com",
    "date":    "2026-03-31",
    "steps":   9200,
    "...": "(all submitted fields)"
  }
}

          

          

            
400 Duplicate

            
{
  "success": false,
  "error": "Record for 2026-03-31 already exists."
}

        PUT
        /api/health/:date
        Auth
        Update an existing health record
        
      

      

        
Updates one or more fields of an existing health record. Only the fields present in the request body are updated — all others remain unchanged. The user_id and date fields are ignored even if supplied.


        

          

            
Path Parameter

            

              
ParamTypeDescription

              
                
datestringYYYY-MM-DD — the record to update

              
            

            
Request Body

            
Any subset of health record fields (same fields as POST). Omitted fields are not touched.

          

          

            
Example Request

            
PUT /api/health/2026-03-31
Authorization: Bearer <token>
Content-Type:  application/json

{
  "steps":      10500,
  "heart_rate": 65
}

        POST
        /api/health/nutrition-lookup
        Auth
        Look up nutrition data for a food description
        
      

      

        
Accepts a natural-language food description and returns estimated nutrition data (fat, carbohydrates, fibre, sugar, sodium) sourced from API Ninjas' nutrition database. Results are aggregated across all foods in the query.


        

          

            
Request Body (JSON)

            

              
FieldTypeReq?Description

              
                
querystringYesNatural language food description, e.g. "2 boiled eggs and toast"

              
            

          

          

            
Example Request & Response

            
POST /api/health/nutrition-lookup
Authorization: Bearer <token>
Content-Type:  application/json

{ "query": "2 boiled eggs and toast" }

// 200 OK
{
  "success": true,
  "data": {
    "fat_total_g":    11.2,
    "carbohydrates_g": 26.4,
    "fiber_g":         1.8,
    "sugar_g":         3.1,
    "sodium_mg":       410
  }
}

        Auth
        Routine Stability Index from recent records
        
      

      

        
Computes a Routine Stability Index (0–100) by analysing the consistency of sleep times, wake times, meal patterns, and exercise frequency from the user's recent health records.

        POST
        /api/analytics/bmi
        Auth
        Calculate BMI and optional exercise calories
        
      

      

        
Calculates Body Mass Index using the WHO formula (weight / height²) and returns the WHO category. Optionally fetches estimated calories burned for a given activity from the API Ninjas caloriesburned endpoint.


        

          

            
Request Body (JSON)

            

              
FieldTypeReq?Description

              
                
weight_kgfloatYesUser weight in kg (20–500)

                
height_cmfloatYesUser height in cm (50–300)

                
activitystringNoActivity name, e.g. "running"

                
duration_minutesintegerNoExercise duration in minutes (default 30)

              
            

          

          

            
Example Request & Response

            
POST /api/analytics/bmi
Authorization: Bearer <token>
Content-Type:  application/json

{

  "duration_minutes": 30
